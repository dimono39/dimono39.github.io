Богатая валидация (16 правил)

Автосохранение (30 сек + при blur/visibilitychange)

Интеграция со всеми модулями

Что болит
1.1. Перегруженная панель действий
Сейчас 15+ кнопок в .actions-grid-premium в один ряд — глаз теряется. Решение: сгруппировать по логическим блокам с заголовками:

text
[ФАЙЛ]      [РЕДАКТИРОВАНИЕ]     [ПРОВЕРКА]         [ЭКСПОРТ]
Импорт      Отменить              Проверить           Excel
Экспорт     Повторить             Отчёт               Резервная копия
Сброс       Объединить разделы    Аналитика           Восстановить
            Копировать день       ИИ-орфография
            Добавить неделю
            Добавить приём пищи
            Создать типовое
Плюс — сворачиваемые группы и сохранение состояния в localStorage.

1.2. Поиск не ищет по разделам и рецептам
Сейчас currentSearchTerm ищет только по item.name. Решение: расширить до name + section + recipeId, добавить чекбоксы «где искать»:

text
[🔍 Поиск...]  [✓ Блюдо] [✓ Раздел] [✓ № рец.]
1.3. Нет быстрого перехода к блюду
При поиске результатов нет — неудобно. Решение: при вводе в поиск показывать выпадающий список «найдено N, перейти к первому». Плюс горячая клавиша Ctrl+F фокусирует поиск.

1.4. Правила — статичные бейджи
Кликнул на правило — перешли к нарушению. Но нельзя:

Посмотреть все нарушения правила списком

Отфильтровать таблицу по правилу

Отключить правило (если оно не критично)

Решение: клик по бейджу открывает мини-модалку:

text
Правило 15: БЖУ ≤ вес
Найдено 7 нарушений

[Показать в таблице] [Отключить правило] [Помощник: как исправить]

Список:
Неделя 1, День 3 — Котлета (100г, БЖУ 120г)  [Перейти]
...
1.5. Дубликаты блюд (правило 17) не подсвечиваются
В checkDuplicateDishes возвращаются дубликаты, но getCellClass ищет их по week и day — а на UI дубликаты часто не видны. Решение: подсветить розовым фоном ячейку name у всех повторяющихся блюд (уже есть класс cell-duplicate, но нужна доработка).

1.6. Нет группировки по дням
Сейчас таблица плоская: неделя → день → приём → блюдо. При 10 неделях × 5 дней × 6 приёмов × 5 блюд = 1500 строк. Решение:

Аккордеон по неделям ([▸ Неделя 1] [▸ Неделя 2] ...)

Внутри — по дням

Или «показывать только нарушения» (сейчас фильтр есть, но неудобен)

1.7. Массовые операции ограничены
Сейчас: удалить, сменить раздел, умножить вес. Решение: добавить:

Копировать выбранные блюда в другой день/неделю

Переместить (не копировать)

Заменить название во всех выбранных

Применить шаблон БЖУ (например, «все каши = 200г, 220ккал»)

1.8. Нет «быстрого ввода» с клавиатуры
Табличный редактор без Tab/Enter-навигации по ячейкам — это боль. Решение: сделать как в Excel:

Tab → следующая ячейка

Enter → вниз

Shift+Enter → вверх

Ctrl+Enter → сохранить и добавить новую строку

1.9. ИИ-орфография работает только по кнопке
Решение: запускать автоматически после загрузки файла (уже есть в init) и после каждого сохранения. Плюс — добавить в словарь новые слова одной кнопкой из модалки исправлений.

1.10. Аналитика не синхронизируется в реальном времени
Если пользователь редактирует меню на вкладке «Редактор», а потом переходит на «Аналитику», данные обновляются (через reload). Но если открыть аналитику в отдельном окне — не увидит изменений. Решение: BroadcastChannel для кросс-вкладочной синхронизации.

📅 Вкладка 2: «Календарь» (#tabCalendar)
Что уже отлично
Красивая сетка дней

Модалка выбора меню для дня

Поиск по блюдам

Экспорт/импорт

Что болит
2.1. Нет массового заполнения календаря
Самый частый кейс: «с понедельника по пятницу — меню 1, следующие 5 дней — меню 2, ...». Сейчас кликать нужно каждый день. Решение: кнопка «Заполнить период»:

text
[📅 Заполнить период]
С: [01.09.2026] По: [30.09.2026]
Меню: [1 ▼] [2 ▼] [3 ▼] ... (циклично)
[✓] Пропускать выходные
[✓] Пропускать праздники (из списка)
[Заполнить]
2.2. Нет шаблонов «учебная неделя»
Школы часто работают по 5-дневке или 6-дневке. Решение: кнопка «Автозаполнение по шаблону»:

5-дневка: Пн–Пт меню 1, 2, 3, 4, 5

6-дневка: Пн–Сб меню 1–6

Чётные/нечётные недели (меню 1-5 / 6-10)

2.3. Каникулы и праздники
Сейчас в календаре можно оставить день пустым, но нет списка праздников. Решение: встроенный список (1 сентября, 1 января, 8 марта и т.д.) + возможность добавить свои. Праздники визуально серые, генератор их пропускает.

2.4. Нет валидации календаря
Пользователь может заполнить календарь и не заметить, что:

15.02 — суббота, но там меню 3 (а по приказу в субботу не учимся)

С 20 по 25 — «дырка» в календаре

Меню 11 не существует в типовом

Решение: кнопка «Проверить календарь»:

text
⚠️ Найдено 4 проблемы:
- 15.02 (суббота) заполнено меню 3, но по настройкам это выходной
- 20.02–25.02 не заполнено (6 дней подряд)
- Меню 11 не найдено в типовом (заполнено 3 дня)
- 01.01 (праздник) заполнено меню 2
2.5. Нет цветового кодирования по меню
Все числа одинаковые. Решение: цвет цифры по номеру меню (1 — синий, 2 — зелёный, 3 — фиолетовый...) — как в генераторе на карточках.

2.6. Нет быстрого копирования дня/недели
Кнопка «Копировать» в календаре отсутствует. Решение:

Клик правой кнопкой по дню → «Копировать», «Вставить», «Очистить»

Или drag-and-drop: перетащить число из одного дня в другой

2.7. Экспорт календаря — только Excel
Решение: добавить экспорт в CSV и PDF (для печати на стенд).

2.8. Нет синхронизации с реальным календарём
Можно интегрировать Intl.DateTimeFormat + isHoliday (готовые библиотеки) для авто-определения праздников и выходных.

Что болит
3.1. Нельзя редактировать «внутри» дня
Сейчас в режиме редактирования можно только заменить блюдо (через модалку). Нельзя:

Изменить вес/калории прямо в списке

Добавить блюдо

Удалить блюдо

Поменять раздел

Решение: в режиме редактирования сделать inline-инпуты:

text
[Название блюда_______] [Вес] [Ккал] [✕]
Или хотя бы кнопку «Редактировать» рядом с каждым блюдом, которая открывает мини-модалку.

3.2. Нет копирования дня
Пользователь выбрал меню 3 для 15.01, а для 16.01 хочет то же самое. Сейчас — выбирать заново. Решение: кнопка «Скопировать в другой день» + модалка выбора даты.

3.3. Нет undo/redo для ежедневного меню
Случайно заменил блюдо — отменить нельзя. Решение: локальный стек истории (5–10 шагов).

3.4. Печать не адаптирована под ежедневное меню
Сейчас printView — для типового. Для ежедневного — printDailyBtn, но без настройки. Решение: отдельные настройки печати (уже есть dailyPrintSettingsModal, но не всё реализовано):

Ориентация

Показывать ли БЖУ

Показывать ли подписи

Сохранять настройки в localStorage

3.5. Нет «сводки дня»
После сборки меню хочется видеть:

text
📊 ИТОГО ЗА ДЕНЬ
Вес: 1 250 г  |  Ккал: 1 890  |  Б: 78 / Ж: 62 / У: 285
Соответствие: ✅
Сейчас эта информация размазана по приёмам. Решение: сводная карточка внизу предпросмотра.

3.6. Даты не синхронизированы с календарём
Если выбрали 15.01 на вкладке Календарь, то на Ежедневном меню не подсветилось. Решение: глобальный selectedDate в общем состоянии, синхронизировать при переключении вкладок.

3.7. Сохранённые варианты — плоский список
Сейчас savedVariants — простой массив. Решение:

Папки/теги (например, «Январь 2026», «Версия для проверки»)

Поиск по имени

Сортировка по дате/имени

Массовое удаление

3.8. Нет «расписания на неделю»
Хочется видеть все дни недели сразу:

text
Пн 09.01 — [меню 1] [предпросмотр]
Вт 10.01 — [меню 2] [предпросмотр]
...
Пт 13.01 — [меню 5] [предпросмотр]
[Собрать неделю]
Решение: новая подвкладка «Неделя» внутри Ежедневного меню.

3.9. Нет валидации «сбалансированности дня»
Считается калорийность завтрака/обеда, но не суточный баланс. Решение: добавить индикатор:

text
🔥 Калорийность за день: 1 890 / 2 200 (86%) — норма
🥩 Б: 78 г / 90 (87%) 
🧈 Ж: 62 г / 77 (81%)
🍞 У: 285 г / 330 (86%)
3.10. PDF не оптимизирован
html2canvas рендерит медленно и с потерями. Решение: использовать pdfmake или jsPDF с autoTable для табличных отчётов — качество и скорость в разы лучше.

Отчёт о нарушениях

Что болит
4.1. Нет фильтров
Нельзя отфильтровать: «только завтраки», «только неделя 2», «только дни с нарушениями». Решение: панель фильтров сверху:

text
[Все приёмы ▼] [Все недели ▼] [Все дни ▼] [Только нарушения ☐]
4.2. Нет сравнения «план vs факт»
Показывается «средняя калорийность», но не сравнение с нормой СанПиН. Решение: столбчатая диаграмма:

text
Приём    | Норма | Факт | Отклонение
Завтрак  | 470   | 420  | -10.6% ❌
Обед     | 705   | 720  | +2.1% ✅
Ужин     | 470   | 485  | +3.2% ✅
4.3. Нет трендов по дням
График «калорийность по дням» — самое важное для анализа. Решение: линейный график (Chart.js / ApexCharts) с зоной нормы (зелёная полоса).

4.4. Нет «тепловой карты» нарушений
Какие дни/приёмы чаще всего нарушаются? Решение: heatmap:

text
        Пн  Вт  Ср  Чт  Пт  Сб
Завтрак  🟢  🟡  🟢  🔴  🟢  ⚪
Обед     🟢  🟢  🟡  🟢  🔴  ⚪
Ужин     🟡  🟢  🟢  🟢  🟢  ⚪
Красный — нарушения, жёлтый — предупреждения, зелёный — OK.

4.5. Нет «топа блюд»
Какие блюда чаще всего повторяются? Какие не используются? Решение: таблица «Топ-10 блюд по частоте» и «Блюда, которые не использовались».

4.6. Нет экспорта аналитики
Только просмотр. Решение: кнопки «Экспорт PDF», «Экспорт Excel», «Ссылка на отчёт» (share).

4.7. Нет сравнения с прошлым периодом
«В январе было 87% соответствия, в феврале — 92%, рост +5%». Решение: селектор «Сравнить с: [Декабрь 2025 ▼]».

4.8. Модуль не обновляется при изменениях
Обновляется только по кнопке «Обновить аналитику». Решение: подписка на menuDataChanged (кастомное событие, которое шлёт редактор после каждого изменения).

4.9. Нет «рекомендаций»
Аналитика показывает проблемы, но не говорит, что делать. Решение: блок рекомендаций внизу:

text
💡 РЕКОМЕНДАЦИИ:
- В 4 днях из 10 завтраки ниже нормы по калорийности. 
  Добавьте калорийные гарниры или масло.
- В меню 3 нет ни одного рыбного блюда. 
  Рекомендуется включить рыбу 2 раза в неделю.
- В среднем на день приходится 3.2 повторяющихся блюда. 
  Разнообразьте меню.
4.10. Нет «сравнения меню 1-10»
Если пользователь ведёт несколько меню, нужно видеть их рядом. Решение: вкладка «Сравнение меню» внутри аналитики — таблица 10×N.

⚙ Общие рекомендации (все вкладки)
5.1. Единый дизайн-язык
Сейчас вкладки стилистически разные:

Редактор — «premium» (градиенты, тени, анимации)

Календарь — «material» (плоский, серый)

Ежедневное меню — «premium-lite»

Генератор — «простой/утилитарный»

Решение: единые токены (CSS-переменные):

css
--app-radius: 16px;
--app-shadow-sm: 0 2px 8px rgba(0,0,0,0.06);
--app-primary: #059669;
--app-bg: #f8fafc;
И единые компоненты: app-btn, app-card, app-modal, app-tabs.

5.2. Навигация «хлебные крошки»
text
Редактор → Меню 3 → Неделя 1 → День 3 → Обед
Сейчас этого нет — пользователь теряется, где он.

5.3. Горячие клавиши
Единый реестр:

Клавиши	Действие
1..6	Переключение вкладок
Ctrl+S	Сохранить
Ctrl+Z / Ctrl+Y	Undo/Redo
Ctrl+F	Поиск
Ctrl+G	Генератор → Сгенерировать
Ctrl+Shift+E	Экспорт полного комплекта
F1	Помощник
?	Все горячие клавиши
5.4. Единый undo-менеджер
Сейчас undo/redo есть только в Редакторе. Решение: глобальный стек, работающий для всех вкладок. Тогда Ctrl+Z отменяет и замену блюда в Ежедневном, и заполнение календаря.

5.5. Онбординг-тур
Для новых пользователей — тур по вкладкам (intro.js или свой). «Это Редактор — здесь меню. Это Календарь — здесь привязка. ...»

5.6. Уведомления (toast)
Единый тост с очередью (сейчас 3 разных системы showStatus).

5.7. Тёмная тема
body.theme-dark + переключатель в шапке. Сохранять в localStorage.

5.8. Локализация
Если проект будет в других странах (Казахстан, Беларусь) — i18n. Вынести все строки в messages.js.

5.9. PWA
Добавить manifest.json + Service Worker → приложение можно установить на телефон/десктоп, работать оффлайн. Особенно ценно для школ с плохим интернетом.

5.10. Логирование действий
Каждое действие пользователя (изменение, экспорт, генерация) — в activityLog. Можно показать в отдельной вкладке «История» или в отчёте «Кто что менял» (для многопользовательской работы).

5.11. Единое автосохранение
Сейчас только Редактор сохраняется в localStorage. Решение: каждое изменение в любой вкладке → localStorage с ключом appState_v*. При загрузке — восстановление всей сессии (редактор + календарь + ежедневные + генератор).

5.12. Импорт/экспорт всей сессии
Один файл .fcmpo (JSON) — вся сессия. Удобно для бэкапа и передачи коллеге.

🚀 Стратегические направления
A. «Проверено ФЦМПО»
Если получится — интеграция с API ФЦМПО для официальной валидации. Огромный плюс для школ, которые отчитываются перед Роспотребнадзором.

B. «Мультишкольность»
Одна установка — много школ. Дашборд администратора, роли (директор, диетсестра, повар), права доступа.

C. «AI-ассистент 2.0»
Расширить SpellCheckerModule до полноценного помощника:

«Составь меню на неделю с учётом СанПиН»

«Замени это блюдо на менее калорийное»

«Проверь сбалансированность и предложи правки»

«Сгенерируй отчёт для проверяющего»

D. «Облако»
Сейчас всё локально. Облачная синхронизация (Firebase/Supabase) — работать с любого устройства, совместный доступ.
